Research notes kept for reference: bypass libwebrtc's video jitter buffer with the field trial `WebRTC-ForcePlayoutDelay/min_ms:0,max_ms:0/` (REA on the shipped LiveKitWebRTC: parsed in the `RtpVideoStreamReceiver2` constructor next to `WebRTC-PacketBufferMaxSize`; overrides any playout-delay RTP extension). Zero min/max puts VCMTiming in zero-playout-delay mode, so frames go to decode as soon as they are complete instead of waiting for the jitter estimate. `WebRTC-ZeroPlayoutDelay` tunes that mode: `min_pacing` (default 8 ms between decodes, timing ctor) and `max_decode_queue_size` (default 8, `VideoStreamBufferController`). Apply with `LKRTCInitFieldTrialDictionary` before `CloudRTCRuntime.peerConnectionFactory` is created. Caveats: field trials are process-wide, so this would also change Xbox unless gated before the factory exists, and changing it needs an app restart. First read the HUD "Jitter buffer" row (delay / target ms) on Bedroom(2) to size the gain; if it already reads near 0, GFN is already negotiating zero playout delay and there is nothing to gain. At 30 Hz the display-locked queue absorbs the extra arrival jitter; above 30 Hz the immediate path would show it.

- Prefer Adaptive Frame Pacing **off** when input feels laggy.
